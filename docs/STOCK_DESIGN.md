# 盤面難易度とアイテムストック設計案

対象：果実日和 v0.6時点の設計履歴。現行v0.7は合計6個・1ステージ3個に変更して実装済み。最新は [STOCK_UPDATE.md](STOCK_UPDATE.md) を参照。

## 1. 結論
ストックは「積み立てた選択肢」であり、盤面の構造欠陥の必須補填にはしない。まずLv11・13・15・17・18・19の障害物による手の減少を調整候補にする。Lv8は48マスあるが、40マスのLv1より通常手が約26%少ない。リングという見た目だけではなく、縦横両方の3マッチが作れる場所の不足が原因となる。

推奨初期設定は共通ストック合計5個、種類別上限はおとどけ3・ライン2・虹1。初期配布はおとどけ1＋ライン1を一度だけ。1ステージの持ち込み使用は最大2個。設計値は初期チューニング案であり、導入後の比較プレイで調整する。

## 2. 評価方法と限界
- 交換候補辺：壁を挟まない上下左右の通常マスの組。
- 構造上有効な交換候補：その辺で、交換前にマッチがなく交換後に3直線または2×2を作れる色配置の例が存在するかを検査。
- H/V：3個直線の窓の数。4個直線には2つの窓がある。個数は互いに独立なチャンスの数ではない。
- 両方向セル：横・縦の3個窓の両方に参加できるセル。4マッチの2×2機会は別計測。
- 幅2以下：各セルから壁・無効マスまでの連続横長/縦長の短い方が2以下となるセル数。実際の地形全体の最小カット幅ではなく、局所幅の指標。
- 接続：通常移動の連結成分数。そのセル1個を除くと成分が増える箇所を関節点として数える。果物の消去で地形自体は消えないため、関節点は脆弱性の目印であって通路が破壊される意味ではない。
- 「開放」は氷・箱をすべて除去した形状。「開始」は実際の氷・箱を移動/マッチ不能として扱う。壁と永久ブロックは両方で維持する。
- 各条件200シード、6種類の通常果物のみ。即時マッチを避けながら色を配置し、有効手がゼロでも除外しない。全20面×2条件=8,000盤面。通常手には2×2成立手も含む。
- サンプルは全安定盤面からの一様抽選ではない。プレイ中の落下の偏り・特殊・目標・プレイヤーの選び方は含まない。「手ゼロ率」は診断用サンプルでの率で、実ゲームの初期手詰まり率でも実際の自動シャッフル率でもない。実ゲームは初期手を保証する。
- 0/200は絶対安全を意味しない。過剰な単一スコアを作らず、複数の指標と実プレイの救済頻度を合わせて評価する。

再実行：`node scripts/evaluate-shapes.mjs`。生データ：`docs/shape-metrics.json`。

## 4. 読み取りと盤面調整案
- Lv1：40マス、両方向40/40、平均8.03手。広い長方形の基準。
- Lv8：48マス、交換候補72本でLv1の67本より多いが、両方向16/48、細幅32/48。平均5.93手。辺を数えるだけでは難しさを捉えられない。上下は縦に3つ、左右は横に3つ並べにくく、中央の空洞が代替方向を奪う。横流入で補充できてもマッチ方向は増えない。
- Lv12：同じ48マスでも開放時平均8.08手。2分割だが各庭が4マス幅で全セルが両方向に参加する。「分断=必ず難しい」ではない。
- Lv10：最大外枠でも開始時7.34手。Lv11の2.58手よりかなり余裕がある。現状の難易度はレベル番号に沿って滑らかには増えていない。
- Lv17：開始時は通常手1.995、関節点17、幅1セル11個。1マス通路と障害物が組み合わさる。中央の一部を2マス幅にし、接続入口に3×3の遊び場を置く。入口の箱を接続線から外す。
- Lv18：開始時1.61手、手ゼロ44/200、15マスの領域2つ。横の3個窓が4しか残らない。各側に3マス幅の膨らみを設け、箱/氷をその膨らみの中央から外す。
- Lv11・13・15・19も開始条件で平均3未満または手ゼロ10%以上。要求個数だけを減らすより、先に入口の障害物を1〜2個ずらす、2×3/3×3の空間を足す方が「自分で崩せる」改善になる。
- Lv8のリングは維持し、上か下の帯を部分的に3マス幅へ広げる案を優先。四隅に3×3の領域を作る案も比較する。幅2以下セルを現状67%から50%以下へ、両方向セルを33%から50%以上へ近づけることを暫定目標にする。

形状検査の暫定注意基準：開始条件の平均手3未満、手ゼロ率10%以上、長い1マス接続、障害物が接続部に集中する場合は要調整。終盤でもストック0でクリア検証を通す。高難度面の長い連続配置を避け、間に幅広い面を置く。

## 5. 共通ストックのルール

| 項目 | 推奨値/動作 | 狙い |
|---|---|---|
| 合計上限 | 5個 | 貯め続けても持ち込み戦力を限定 |
| 種類上限 | おとどけ3、ライン2、虹1（合計5も同時適用） | 強い虹を貯め込みにくくする |
| 初期所持 | おとどけ1、ライン1、虹0 | 最初から使い方を試せる |
| 1面の使用 | 合計2個まで | 1面を全アイテムで押し切りにくくする |
| 回収 | 初回クリア時の連鎖・落下完了後、残っている全特殊を回収候補へ | 温存を評価する |
| ラインの統合 | 縦/横の内部種別を共通ライン在庫へ合算 | 使用時に交換方向で向きを選べる |
| 回収優先 | 虹→ライン→おとどけ、種類内はセル番号順 | 上限超過で強い報酬が不意に失われるのを避ける |
| 超過 | 追加せず、回収数と上限超過数をクリア画面に表示 | 裏で入れ替えたり換金したりしない |
| 再クリア | 新規回収報酬なし | 簡単な面を周回して常時補充する抜け道を防ぐ |
| 自動配布 | 毎ステージ配布はしない | 温存と消費の価値を保つ |

「全クリアで必ず回収」を採用すると低難度周回で上限まで毎回補充できるため、推奨案は初回クリア限定の回収。これは意図的な制約で、クリア済み面には「回収済み」と明示する。再プレイを報酬ループにしたい場合は別設計とする。

既存在庫は入れ替えない。例：おとどけ3＋ライン2で満杯なら、クリア時の虹も追加できない。入れ替え確認を毎回出すより単純さを優先する。後に不満が出れば「回収前の交換」UIを検討する。

## 6. 使用方法
1. 右操作欄の「ストック 2/5」を開く。3種類と個数を表示。盤面は隠さない小さなパネルにする。
2. アイテムを選び、通常果物のマスを選ぶ。この時点ではプレビューで在庫を減らさない。
3. 隣の通常果物を選んで交換方向を指定。ここで投入・スワップ・発動を一つの操作として確定し、在庫を1個減らす。キャンセル無料。

投入先・交換先は壁を挟まない通常果物のみ。氷・箱・無効空間・既存特殊には投入不可。置き換えた果物は収穫に数えない。ストックから既存特殊への即合成は初版では不可（虹連打による難度崩壊を避ける）。盤面上で自然生成した特殊同士の合成は維持する。

おとどけの発動先選定は現在の先読み、ラインは交換方向、虹は交換相手の種類を利用する。既存ルールを再利用し、別の強化版にはしない。プレビュー中はゲームを進めず、確定後の連鎖中は全入力をロック。

## 7. 手詰まりとストック
ここを変更しないと、ストックを導入しても自動シャッフルに先を越される。

1. 通常手または盤面上の発動手がある：通常プレイ継続。
2. どちらもないが、在庫・使用枠・有効な投入先がある：「ストックを使う / シャッフル」を提示し、プレイヤーの選択を待つ。勝手に在庫は消費しない。
3. 在庫0、2回使用済み、または有効な投入先がない：従来の最終救済シャッフル。

おとどけ先読みの試行用盤面ではユーザーへの選択待ちを起こさない。試算と実プレイの責務を分離し、エンジンは「手なし」を返し、アプリ側でストック案内かシャッフルを選ぶ。クリアが確定した盤面では手詰まり案内を出さず回収へ進む。

## 8. 保存・再挑戦・重複防止
- 既存localStorageキーは維持し、データversionを2へ。`stock: {delivery, line, rainbow}`、`stockIntroGranted`、`stockRewardedLevels`、`stockUsesByLevel` を追加する。
- v1からv2へ移行時も最高到達・クリア済み・音/動き設定を維持。初期2個は新規/既存ユーザーとも導入時に一度だけ。過去クリア済み面は回収済みとみなし、存在しない過去の残アイテムは遡及付与しない。
- 在庫・使用回数を確定時に一括保存。ページ更新・やり直し・別レベル経由でも使用済み在庫を戻さない。使用回数の2回枠はレベル別に記録し、その面をクリアするまでリセットしない。クリア後の新たな再プレイは2回枠から始められるが回収報酬はない。
- クリアの判定、在庫回収、回収済みID、最高到達、クリアIDを単一の保存オブジェクトで更新する。「次へ」ではなくクリア確定時に保存し、閉じる・再読み込みで二重回収しない。
- 確定したストック使用のエンジン結果を先に計算し、成立する場合だけ消費して保存。入力不正・長連鎖キャンセルなどの不成立で消費しない。演出はその後。
- 途中盤面は従来通り保存しない。再読み込みでやり直すと使用済みアイテムは戻らない旨を設定/確認画面に表示。演出中でも在庫は確定済み。
- 型チェック、整数化ではなく不正値排除、0以下/種類上限/合計上限の検証。stockIntroGranted=trueで在庫が壊れていても配布を繰り返さない。
- localStorage失敗時はメモリで継続し「ストックは今回のプレイ中のみ保持」と表示。同一端末の複数タブはセーブ更新を監視し、別タブ更新後は再読込を促して競合使用を防ぐ。サーバーなしでユーザー自身による保存改変まで防ぐ仕様にはしない。

## 9. バランス検証と導入順
1. まずLv8・17・18の形状候補を2案ずつ作り、同じ200シードで指標を比較する。全20面の形状データ変更は今回未実施。
2. stock0の基準、初期2個だけ、前面からの回収あり、の3条件で同じシードをプレイ。自然生成特殊の使用方針を統一する。
3. 初期目標：高難度面の自動シャッフル回数/100操作を基準から30%以上減らす。これは未検証の目標値。ゼロを強制すると盤面が単調になりうる。
4. クリア時在庫、使用回数、回収超過、クリア操作数、通常手ゼロの滞在、ストック案内後の選択をローカル検証用に集計。多くの人が全高難度面で2個必須なら形状側を再調整。常に5個で余るなら回収率/上限を見直す。
5. 自動テスト：v1移行、一度だけ初期配布、全上限、同時回収、再クリア無報酬、二重クリア、失敗使用無消費、やり直し枠維持、投入先制約、手詰まり案内、先読み中の在庫不変、保存失敗。
6. Chromeの横向きPC/スマホでストック表示・プレビュー・方向指定・キャンセル・連鎖中ロック・クリア回収・再読込を確認。保存互換と既存ゲームの回帰が通ってから公開する。
